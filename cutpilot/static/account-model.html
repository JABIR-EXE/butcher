FOUNDER / DEPLOYMENT GUIDE · CUTPILOT v1.8

How each butcher will use CutPilot

Commercial direction: a hosted website with individual owner accounts. Butchers use a browser; they do not install the app or run a database.

Current truth: v1.8 contains a working early account pilot. It has not been deployed to a public domain, billing is not connected, and the current tenant database method is a single-instance SQLite pilot rather than scalable managed PostgreSQL.

1. What the butcher experiences

  1. The butcher visits your public CutPilot website.
  2. They compare plans and create an owner account.
  3. They verify the email address and sign in.
  4. They enter the business name, country and currency.
  5. They import their product catalogue and opening stock, then POS sales exports.
  6. They review sales, stock alerts and suggested purchases.
1 · Public websitePlans, registration and sign-in
2 · Owner accountOne owner and one business workspace in v1.8
3 · Private shop dataSeparate business database file on the hosted pilot

2. What the v1.8 account pilot implements

  • Owner registration, sign-in and sign-out.
  • Email verification and password-reset emails when SMTP is configured.
  • Session cookies and server-side account-to-workspace lookup.
  • One SQLite database file per organization on the same host's persistent disk.
  • Authenticated business API routes and cross-business isolation tests.

3. What is not implemented yet

  • Public deployment at your own domain — the included Render Blueprint is a template only.
  • Managed PostgreSQL and database row-level security for a scalable multi-tenant service.
  • Employee invitations, multiple roles and multiple workspaces per owner.
  • Subscription checkout, payment webhooks, cancellation, invoices or paid-plan enforcement.
  • Automated production backups, restore drills and an independent security review.

4. Local preview versus account test versus hosted pilot

  • Local preview: run py app.py with the default local mode. It has one shop database on your computer and is best for a product demo with sample data.
  • Local SaaS test: set CUTPILOT_MODE=saas and CUTPILOT_DATA_DIR to a separate test folder. This lets you register two fake accounts locally and test that their shop data is isolated.
  • Hosted pilot: deploy the SaaS mode on a paid service with persistent storage, HTTPS, a real domain and transactional email. Keep it invite-only and one instance while using the SQLite tenant-file model.

5. What should happen before scaling

Migrate to managed PostgreSQL. Every business-owned record should carry an organization relationship, and the database should enforce row-level security as well as application membership checks. Add private import storage, encrypted backups, restore tests, monitoring, staff roles, data export/deletion and a professional security review.

6. Pricing and money

Starter ($29/month), Professional ($59/month) and Multi-location ($99+/month) are proposed prices only. A butcher can select a preferred plan while registering, but v1.8 does not collect money or activate a paid subscription. Integrate an approved payment provider, signed server-side webhooks and plan enforcement before selling subscriptions.
